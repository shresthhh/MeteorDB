# MeteorDB Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a durable embedded Rust LSM-tree engine with snapshots, prefix scans, leveled compaction, and typed inference-cache, feature-store, and embedding adapters.

**Architecture:** MeteorDB uses one serialized WAL-backed write path, ordered in-memory tables, immutable block-based SSTables, a manifest-backed version set, concurrent snapshot readers, and background flush/compaction workers. AI modules remain typed adapters over the ordered byte key/value core so storage correctness and workload specialization can evolve independently.

**Tech Stack:** Rust 1.88.0 with the 2024 edition, Cargo workspace, `bytes`, `crc32c`, `thiserror`, `parking_lot`, `fs2`, `snap`, `blake3`, `serde`, `postcard`, `clap`, `hdrhistogram`, `proptest`, `tempfile`, `criterion`, and `cargo-fuzz`.

## Global Constraints

- Deployment is an embedded, single-node library; do not add a network server.
- MeteorDB is not RocksDB API-compatible or file-format-compatible.
- The core stores lexicographically ordered byte keys and byte values.
- Writes are serialized; reads may execute concurrently at snapshot sequence numbers.
- Promise atomic write batches and snapshot-isolated reads, not general transactions.
- `Sync` durability acknowledges only after `fsync`; `Buffered` durability requires explicit synchronization for a stable-storage guarantee.
- Corruption must return a typed error and must never become a cache miss.
- Linux is the primary platform; portable synchronous file I/O is the correctness baseline.
- Pin the repository toolchain to Rust 1.88.0 with `rustfmt` and `clippy`.
- ANN/vector similarity search, replication, column families, and parallel write queues remain out of scope.
- Every public feature must document what it does, why it exists, how it works, and its trade-offs.

- [ ] **Step 3: Implement the WAL format**

Use a 32 KiB physical block and a seven-byte fragment header:

```text
crc32c: u32 little-endian
length: u16 little-endian
fragment_type: u8 = FULL | FIRST | MIDDLE | LAST
```

The logical payload is:

```text
format_version: u8
sequence: u64
operation_count: u32

```

Mask checksums before storage, validate all lengths before allocation, ignore
only an incomplete final logical record, and return `Error::Corruption` for an
earlier checksum or fragment-order failure. `DurableFs` wraps create, append,
file sync, directory sync, and atomic replace so crash injection can replace
it later.
