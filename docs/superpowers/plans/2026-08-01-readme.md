# MeteorDB README Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an accurate developer-first README with a runnable quickstart and explicit implemented-versus-planned feature status.

**Architecture:** The root `README.md` is the project entry point. A checked `crates/meteordb/examples/quickstart.rs` file is the single source for the runnable API example so the documented workflow is validated by Cargo rather than relying on an uncompiled Markdown snippet.

**Tech Stack:** Markdown, Rust 1.88.0, Cargo examples.

## Global Constraints

- Stay on the existing `feature/meteordb-engine` branch; do not create another branch.
- Describe only code present in the repository as implemented.
- Mark SSTables, Bloom filters, compaction, scans, TTL enforcement, recovery, and AI adapters as planned.
- Do not publish performance claims or badges before their supporting systems exist.
- Keep commands executable from the repository root.
- Use the actual public `meteordb` API in the quickstart.

### Task 1: Add Developer README and Runnable Quickstart

**Files:**
- Create: `README.md`
- Create: `crates/meteordb/examples/quickstart.rs`

**Interfaces:**
- Consumes: `meteordb::{Engine, Options, Result, WriteBatch}`.
- Produces: a repository landing page and `cargo run -p meteordb --example quickstart`.

- [ ] **Step 1: Add the runnable quickstart**

Create an example that opens a temporary path supplied through
`std::env::temp_dir`, writes one atomic user/profile batch, captures a snapshot,
updates one key, verifies the snapshot still observes the old value, prints the
current value, and closes the engine. Remove the example database directory
before and after execution so repeated runs are deterministic.

- [ ] **Step 2: Run the example**

Run: `cargo run -p meteordb --example quickstart`

Expected: prints the current profile value and exits successfully.

- [ ] **Step 3: Write the developer-first README**

1. MeteorDB definition and experimental status.
2. Current implementation summary.
3. Rust 1.88.0 prerequisite.
4. Clone, build, test, and quickstart commands.
5. A short API excerpt matching `examples/quickstart.rs`.
6. A plain-language write-path explanation.
7. An implemented/planned feature table.
8. AI workload goals without benchmark claims.
9. Links to the design and implementation plan.
10. Contribution validation commands.
